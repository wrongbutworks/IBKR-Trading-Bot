BouncyBot - IBKR Portable Trading Bot v3.3.0
Corrected implementation and verification report
Release date: 2026-07-26

BASELINE
========

The supplied archive
IBKR_Trading_Bot_3.2.2_Branding_About_Documentation_Source(1).zip was used as
the implementation baseline. Its locally modified documentation and source
content were retained. The release was not reconstructed from an earlier
repository snapshot.

FINAL V3.3.0 CHANGES
====================

1. Automatic and manually selectable Fusion themes

- Startup checks Qt's operating-system color scheme before the main window is
  created and applies the corresponding Fusion palette and stylesheet.
- Supported live QStyleHints.colorSchemeChanged notifications update the
  running application when the operating-system theme changes.
- A View menu is placed between File and About and provides Light mode and Dark
  mode actions for immediate in-process switching.
- Manual theme choices are session-only and do not add a SQLite setting or
  database migration.
- The dark palette uses neutral Qt Fusion-style greys rather than the earlier
  navy/slate treatment.
- Cached state widgets and custom-painted Timeline, Profit Guard, strategy graph,
  and flowchart surfaces are refreshed after a theme change.

2. About-screen logo layout

- The logo is contained in a dedicated fixed-height panel.
- Its scaled size is bounded for high-DPI displays and retains aspect ratio.
- The title, version, and repository link are laid out after the complete logo
  panel, preventing text overlap and lower-edge clipping.

3. Cycle Audit Timeline tables

- Compact fields retain bounded content-based widths.
- Both tables expand across the available horizontal row instead of leaving a
  large unused area.
- The transition and guard/risk tables receive a 3:2 width allocation.
- Each Message column stretches into remaining space; horizontal scrolling is
  retained only for genuinely over-wide content.
- Full cell values remain available through tooltips.

4. Cycle Audit Market capture layout

- The Market capture tab no longer uses a page-level vertical scroll area.
- Metadata, captured-row preview, and capture-file sections fit directly inside
  the tab viewport.
- Individual data boxes own their vertical scrollbars when their content exceeds
  the bounded section height.

5. Windows release layout

- PyInstaller remains a one-directory build under GUI/.
- Only BouncyBot_app_icon.png and BouncyBot_logo.png are included as runtime
  image data, plus BouncyBot_app_icon.ico as the executable icon.
- The complete source Images/ directory is not copied to the portable Windows
  release root.
- BouncyBot.lnk is created in the release root and targets
  GUI\IBKRTradingBot.exe, including a relative-path fallback for portability.
- QUICK_START.txt documents both the shortcut and direct executable path.

6. Release and documentation maintenance

- Application, package, build, changelog, security, documentation, and tests
  remain versioned as v3.3.0.
- The v3.2.2 release note remains archived under docs/legacy/.
- docs/V3_3_0_DARK_MODE_AUDIT_AND_WINDOWS_RELEASE.md describes the final
  corrected v3.3.0 behavior.

SAFETY AND COMPATIBILITY
========================

No strategy transition, broker order construction/submission, price selection,
quantity calculation, risk guard, session policy, reconnect logic,
reconciliation, recovery, execution accounting, commission handling, P/L
calculation, or persisted setting was changed.

No SQLite table, column, index, migration, or theme field was added. Existing
v3.2.2 databases, settings, active cycles, orders, executions, audit events,
backups, exports, and market-capture files remain compatible.

Theme detection and manual theme selection are presentation-only and cannot
affect trading state.

CORRECTIVE-REVISION VERIFICATION
================================

Repository tests
----------------

- 1,059/1,059 collected pytest cases passed across isolated test-file
  partitions.
- ResourceWarning was promoted to an error throughout the partitioned run.
- 55 focused tests covering the corrected v3.3.0 GUI, theme, About, audit-layout,
  Windows-build, main-entry, import-stub, and documentation behavior passed.

Coverage and deterministic verification
---------------------------------------

- 77.9% combined statement/branch coverage for app/ and main.py; required gate:
  75.0%.
- 945/945 effective executable application callables were entered.
- The two runtime-threshold large-database performance tests passed separately
  without Coverage.py instrumentation, because instrumentation invalidates their
  elapsed-time limits. The remaining 1,057 tests produced the coverage report.
- 17/17 targeted safety mutants were killed.
- 58/58 deterministic simulation contracts passed across 54 CSV files.

Supplemental verification
-------------------------

- Python compileall passed for app/, tests/, scripts/, and main.py.
- git diff --check passed.
- Ruff and Pyright were not installed in the offline Linux environment and are
  not recorded as passing. The Windows run_all_tests.bat workflow still requires
  both tools.

Platform-specific boundary
--------------------------

A native Windows executable was not built in this Linux environment. PyInstaller
binaries and Windows .lnk behavior are platform-specific. Run build_windows.bat
on Windows to assemble and smoke-test the binary package before publishing it.
